## ADDED Requirements

### Requirement: 独立 ARC 视觉标记
ARC 版本 MUST 使用原创的像素拱门与星点图形，统一入口、职业选择、主城、网页顶栏和浏览器图标；可见画面 MUST 不再绘制 Rialo 标记或 RIALO 品牌文字。

#### Scenario: 查看各游戏入口与主城
- **WHEN** 玩家启动 ARC 版本、选择职业或进入主城
- **THEN** 显示原创 ARC 图形与 ARC 标题，不显示旧 Rialo 图形或 RIALO 标题。

#### Scenario: 查看网页品牌
- **WHEN** 玩家查看网页顶栏或浏览器标签页
- **THEN** 使用与游戏内一致的拱门和星点图标。

### Requirement: 独立可玩的 ARC 目录
系统 MUST 在 `arc-rpg/` 提供独立启动和验证命令，保留现有地牢、职业、主城和本地结算玩法，并使用独立本地存储命名空间。

#### Scenario: 游客启动
- **WHEN** 玩家在没有钱包和后端配置的环境启动 ARC 版本
- **THEN** 游戏允许游客游玩，并且不读写 Rialo 存档。

### Requirement: 测试网钱包连接
系统 MUST 支持 EIP-1193 钱包连接、Arc Testnet 切换、未知网络添加及账户/链变更；MUST 在提交前重新验证账户与 chain ID 5042002。

#### Scenario: 钱包未添加测试网
- **WHEN** 钱包切链返回 4902
- **THEN** 系统提供官方测试网配置，添加后重新切换并验证结果。

#### Scenario: 拒绝或断开连接
- **WHEN** 玩家拒绝连接或钱包断开
- **THEN** 界面显示中文状态，游戏仍可继续，禁止发布战绩。

### Requirement: 主动发布结算战绩
系统 MUST 仅在本地结算成功后准备战绩，玩家主动点击后通过零金额自转账发布公开 JSON 数据；MUST 标识战绩为玩家自行提交且游戏经济仍为本地模拟。

#### Scenario: 结算后发布
- **WHEN** 玩家连接测试网并主动发布已结算战绩
- **THEN** 交易 from/to 均为当前钱包，value 为零，input 包含协议版本、runId、职业、种子、层数、Boss 数、探索率和结束原因。

#### Scenario: 网络或账户已改变
- **WHEN** 点击发布后钱包账户或网络与准备时不一致
- **THEN** 不广播交易，提示玩家重新连接正确账户和网络。

### Requirement: 交易确认与幂等恢复
系统 MUST 区分待签名、待确认、已确认、执行失败、查询失败；仅在链 ID、收据状态与原交易数据验证通过后显示已确认。待确认交易 MUST 持久化并能在刷新后继续查询，同钱包同战绩的 pending/confirmed 记录禁止重复广播。

#### Scenario: RPC 暂时失败
- **WHEN** 交易已广播但查询暂时失败或超时
- **THEN** 保留交易 hash 与待确认状态，允许继续查询并显示交易链接，不自动重发。

#### Scenario: 链上执行回滚
- **WHEN** 收据 status 为 0x0
- **THEN** 显示执行失败，不视为链上成功，并允许玩家主动重试。

#### Scenario: 钱包切换后恢复
- **WHEN** 玩家重新连接曾提交的账户并刷新页面
- **THEN** 展示该账户的战绩与交易状态，不把其他账户的交易显示为当前账户战绩。
