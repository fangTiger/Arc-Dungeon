## Context

现有项目是原生 JavaScript + Canvas 像素游戏，门票、皮肤和结算由本地 Mock 账本完成。用户确认保留玩法，新增钱包、切换测试网和链上战绩，并在新目录独立开发。原工作区存在数据库相关未提交改动。

## Goals / Non-Goals

**Goals:** 独立可启动的 `arc-rpg/`；无需账户服务即可游玩；支持注入式 EVM 钱包；仅在 Arc Testnet 发布结算战绩；确认交易后给出可验证链接；独立存档。

**Non-Goals:** 首版不迁移 Discord 后端、数据库或现有环境变量；不发行代币、收费门票或链上奖励；不声称战绩具备防作弊保证。

## Decisions

**原创 ARC 标记补充：** 使用 16×16 基础网格的拱门形 A 与星点。Canvas 根据整数矩形绘制，顶栏和 favicon 的 SVG 从相同矩形列表生成。浅蓝门户配暖金星点与现有地牢风格融合。相较直接使用官方图形，原创标记能适配游戏像素网格；相较仅用 ARC 文字，它能统一网页和游戏内识别。修复入口与主城残留旧品牌，不改动原 Rialo 目录。

1. **独立前端快照。** 在 `arc-rpg/apps/web/` 复制原前端源代码、美术与带许可证的 vendor，新增本地 package 和开发命令。相比跨目录导入，快照允许未来独立部署；相比重写，保留现有战斗与场景。后续玩法修复需要显式同步。
2. **轻量钱包适配。** 使用 EIP-1193 provider，不引入 React 或钱包依赖。先连接，再主动切换；未知链添加后重新切换并验证链 ID。账户/链变化更新状态，提交前再次查询账户和链。原游客存档仍可玩，钱包只负责战绩归属，不把钱包连接视为服务端身份认证。
3. **数据交易战绩。** 本地结算成功后触发 ARC 事件，按固定字段整理协议为 `arc-rpg:run:v1` 的公开 JSON，编码为 UTF-8 十六进制 calldata。通过 `eth_sendTransaction` 向当前钱包自身发送 `value: 0x0` 的交易。相比合约，此方式不要求提前部署；相比仅保存哈希，浏览器可直接读取完整战绩。交易消耗测试 USDC gas。
4. **提交与确认分离。** 点击发布才请求签名；收到 hash 后状态为 pending，轮询收据且校验成功、from/to/value/input 和链。刷新后恢复同一钱包、同一 run 的待确认交易，避免重复广播；明确失败才允许重试。断网或超时保留 pending，提供继续查询。
5. **存档隔离。** ARC 的经济、语言和 OAuth 存储键采用 `arc:`/`arc.` 前缀。战绩以 wallet + chainId + runId 标识并本地持久化。存储不可用时给出提示，当前会话继续运行。

## Risks / Trade-offs

- 客户端战绩可被修改 → 界面及文档明确为玩家自行提交，不据此发放链上奖励。
- 交易失败、拒签或网络变更 → 保留本地结算；提交失败不阻断游戏。
- 测试网参数会变化 → 配置集中在一个模块，记录官方来源与核验日期。
- 快照产生重复源码 → 用原游戏回归测试与 ARC 专属测试验证，并记录来源。

## Migration Plan

直接新增目录，无数据库迁移。进入 `arc-rpg` 后执行 `npm run dev`，使用独立端口 5174。原版本继续使用现有命令。移除新增目录即可撤销 ARC 版本。

## Open Questions

后续如需要合约排行榜、防作弊结算或 USDC 门票，另建 OpenSpec 变更。首版真实钱包广播需要玩家安装钱包并从官方水龙头领取测试 USDC。
